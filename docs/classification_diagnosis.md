## 1. 실행 요약

| 단계 | 명령 | 결과 |
|---|---|---|
| 사전점검 | `.env` 키/DB 확인 | `DATABASE_URL` **OK**(Supabase Postgres + pgvector 0.8.0), `OPENAI_API_KEY`만 존재(→`LLM_API_KEY` 폴백). `UPSTAGE_API_KEY`/`LLM_API_KEY` 미설정 |
| fetch | `python main.py fetch` | **성공**, 신규 5건 (피드 대부분 캐시됨) |
| crawl | `python main.py --crawl-batch-size 40 crawl` | **성공** (exit 0, LLM 불필요) |
| process | `python main.py --ai-batch-size 10 process` | **실패** — 모든 기사에서 `401 invalid_api_key` |
| 임베딩 검증 | `embed_query()` 단발 호출 | **실패** — 동일 `401 invalid_api_key` |
| classify_events / classify_topics | — | **실행 불가**(LLM·임베딩 둘 다 401) |
| 결과 검수 | `ensure_db` + SELECT only | **수행** (기존 누적 결과 대상) |

**핵심 제약**: `.env`의 `OPENAI_API_KEY`가 `LLM_BASE_URL`(Upstage)에 대해 **인증 실패(401)**. 챗·임베딩 모두 막혀 **신규 분류를 한 건도 생성하지 못했습니다.** 따라서 본 검수는 **DB에 이미 누적된 결과**(article_ai_results 4,516 event_assigned, events 3,127, event_articles 4,669, topics 83, topic_causes 176)를 읽기 전용으로 분석한 것입니다. 없는 결과를 지어내지 않았습니다.

**부수 영향(투명 보고)**: 실패한 `process` 실행이 invalid-key로 재시도하며 `article_jobs`를 pending→failed로 일부 이동시켰습니다(failed 3,049→3,129, pending 284→261). 분류 결과 테이블(events/topics/event_articles)에는 영향 없음.

> 참고: 코드상 **서브토픽 기능은 존재하지 않습니다**(테이블·로직 없음) → 서브토픽 검수는 N/A.

## 2. 분류 결과 검수 (실데이터 인용)

### 2-1. 이벤트 — 묶음(cohesion)은 우수, 같은 사건 분열(over-create)이 문제

**잘 된 사례 (다매체 병합 우수, over-assign 거의 없음)**

- **event 638 「윤석열 전 대통령 평양 무인기 침투 지시 1심 선고」 (23기사 / 11개 매체)**: 경향·미디어오늘·아시아경제·프레시안·조선·동아·한겨레·JTBC·SBS·세계·뉴시스 — **진보~보수 전 스펙트럼**이 한 이벤트로 정확히 병합. reason 대부분 "주체, 장소, 혐의, 선고 내용이 동일". 23건 중 혼입 의심은 1건뿐(이준석의 "무인기를 보내든 달러를 보내든" **정치적 비유 발언** — 같은 판결이 아닌 반응성 코멘트, 경미한 over-assign).
- **event 1871 「SK하이닉스 신입 채용 학력 제한 폐지」 (14기사 / 13개 매체)**: 전부 동일 발표 사건. reason "주체, 날짜, 핵심 행위 일치". 혼입 0건.
- 정량: 다(多)기사 이벤트(725건) 중 **518건이 2개 이상 bias 버킷에 걸침** → 핫이슈의 교차매체 병합이 잘 작동.

**오분류 — 과생성(over-create): 같은 사건이 여러 이벤트로 쪼개짐**

| 정상(병합본) | 분열된 중복 이벤트 | 분열된 기사 reason |
|---|---|---|
| ev638 (무인기 선고, 23기사) | **ev1497** (1기사) 「…1심 징역 30년 선고」 | "1심 선고 및 무인기 투입 혐의" |
| | **ev1665** (2기사) 「…작전 1심 징역 30년 선고」 | **"기존 후보 중 동일 구체적 이벤트 없음"** |
| ev2017 (일본은행 금리, 12기사) | **ev2515** (1기사) 「일본은행 기준금리 인상」 | **"미국 압박 언급으로 구체적 행위 차이"** |

- ev1497: 프레시안 **칼럼**("윤석열이 드러낸 최첨단 극우")이라 임베딩이 판결 사실에서 벗어나 후보 검색(거리 0.45) 통과 못 함 → 후보 0개 → **LLM 없이 직접 신생성**.
- ev1665 / ev2515: 후보(ev638/ev2017)가 있었는데도 **LLM이 "같은 구체적 이벤트 아님"으로 create 판정**. 둘 다 같은 판결/같은 금리인상의 **후속·해설 기사**인데 "내란죄 형량"·"미국 압박" 같은 부가 프레임을 "다른 행위/상태"로 오인.
- 추가: **이재명 G7 참석**이 ev1809(환영식·30초 대화)/ev1828(정상회의)/ev1852(만찬·김혜경 소개)로 **1분 내 3개 이벤트로 분열**(같은 G7 참석일).

## 3. 정량 지표

**표본/모집단**: DB 전수 + 핵심 사례 정밀 인용. UTF-8 강제 후 SELECT 집계.

| 지표 | 값 | 해석 |
|---|---|---|
| 단일기사 이벤트 | **2,402 / 3,127 = 76.8%** | 강한 파편화 신호 |
| **후보 0개 → 직접 생성**(reason='검색 후보 없음') | **1,531 / 4,669 매핑 = 32.8%** | 배정의 1/3이 LLM 중복검사 없이 신생성 |
| 다기사 이벤트 중 ≥2 bias 버킷 | 518 / 725 = 71.5% | 교차매체 병합 양호(긍정) |
| 대형 이벤트 cohesion(정밀검수) | 638·1871 = 37기사 중 혼입 1건(이준석 발언) | **over-assign ≈ 2.7%, 매우 낮음** |
| 확인된 이벤트 over-create | 최소 무인기 3건(1497/1665/2681), 일본금리 1건(2515), G7 분열 2건 | over-create가 지배적 오류 |
| 단일이벤트 토픽 | **71 / 83 = 85.5%** | 토픽도 파편화 |
| 확인된 중복 토픽 | t74=t75(완전중복), 미·이란 MOU 3토픽, 이재명 순방 7토픽 등 | 토픽 over-create 존재 |
| 토픽 체인 시간순 | 실데이터 토픽 정확, 시드 토픽 77 1건 역전 | 파이프라인 체인 로직은 정상 |

**결론**: over-assign(무관 기사 혼입)은 매우 드묾(가드레일·프롬프트의 "같은 구체적 이벤트만 assign"이 잘 작동). 지배적 오류는 **over-create(같은 사건/주제의 분열)**.

## 4. 개선 가설 (원인 추정 → 권장 방향, *추측 표시*)

1. **후보 검색 2일 윈도우 + 거리 0.45가 후속/칼럼 기사를 탈락시킴** → 후보 0개 직생성(32.8%).
   - 근거: `src/db/events.py:71-80` `SEARCH_CANDIDATE_EVENTS_SQL`의 `updated_at + INTERVAL '2 day' >= ?` + `<=> <= 0.45`. ev1497(칼럼)이 이 경로로 분열.
   - 권장(*추측*): 핫이슈에 한해 윈도우를 3~4일로 완화하거나, `EVENT_DISTANCE_THRESHOLD`(`src/event_classifier/settings.py:11`, 기본 0.45)를 0.50~0.55로 소폭 상향해 후보 회수율↑. 단 over-assign 재상승 모니터 필요.

2. **이벤트 배정 프롬프트가 create로 과편향** → 같은 판결의 해설/반응 기사를 별도 이벤트로 판정(ev1665, ev2515).
   - 근거: `src/event_classifier/prompts.py:65,72` "distance 높거나 직접 상관 약하면 create", "후속 전개라도 핵심 행위/절차 상태 다르면 보통 create". "미국 압박 언급"·"내란죄 형량"을 *다른 행위*로 해석.
   - 권장(*추측*): 프롬프트에 "동일 판결/발표에 대한 **반응·해설·추가 분석**은 같은 이벤트로 본다"는 예외 규칙 추가(prompts.py:68-79 블록).

3. **토픽 후보 검색의 카테고리 하드필터가 동일 사안을 분열**(미·이란 MOU: 경제 t59 vs 국제 t53/t12).
   - 근거: `src/db/topic_causes.py:39` `AND t.category = ?::category`. **코드 주석(25행 "카테고리 구분 없이 전체 토픽 대상")과 실제 SQL이 모순** — 실제로는 카테고리 필터링됨.
   - 권장(*추측*): 토픽 검색에서 카테고리 필터를 제거하거나, 거리 가중 후보에 한해 cross-category 허용.

4. **t74=t75 완전중복 토픽** → 토픽 신생성 시 동일 제목/근접 cause 중복 방지 가드 부재.
   - 근거: `src/topic_classifier/pipeline.py:228-234` create 분기에 중복 토픽 체크 없음.
   - 권장(*추측*): create 직전 동일 category·동일/근접 제목 토픽 존재 시 재검사.

5. **`MIN_NET_ARTICLE_COUNT=5` 때문에 분열된 소형 이벤트(ev1497/1665 등)는 토픽 승격 자체가 안 됨** → 토픽 단계의 보정 기회 상실(`settings.py:9`). over-create를 이벤트 단계에서 줄이는 것이 더 효과적(*추측*).

## 5. 미검증 항목

- **신규 E2E 분류(process/event/topic)**: LLM·임베딩 401로 **실행 불가**. 위 진단은 전부 *기존 누적 결과* 기반이며, 임계값 변경의 실제 효과는 키 복구 후 재실행으로만 검증 가능.
- **score 필드**: `event_articles.reason`만 영속화되고 LLM `score`는 DB에 저장되지 않아 배정별 점수 분포는 직접 검증 불가(임계 가드레일 동작은 reason 텍스트로만 간접 확인).
- **토픽 체인 정확성**: 실데이터 멀티이벤트 토픽이 소수(약 12개)이고 그중 다수가 **시드 데모 데이터**라 표본이 작음.
- **필요 조치**: 유효한 `UPSTAGE_API_KEY`(또는 Upstage용 `LLM_API_KEY`) 설정 후 `embed_query()` 단발 검증 → 통과 시 `process`→`classify_events`→`classify_topics` 재실행으로 본 리포트 가설을 확증 권장.
