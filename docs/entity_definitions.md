## 토픽

**목적**: 하나의 사회적 이슈를 구성하는 연관된 사건들을 포괄하는 최상위 단위.

**정의**: 인과관계, 동일 이슈, 동일 일정, 동일 사회적 현상으로 묶이는 사건들의 집합.

**생성 기준 (네이밍 테스트)**: 각 이벤트명 앞에 토픽명을 붙였을 때("<토픽명> — <이벤트명>") 사건
전체 이름이 자연스러우면 성공. 예: "2026년 6.3 지방선거 — 사전투표 부실 논란"은 자연스럽지만,
"사회 — 사전투표 부실 논란"은 부자연스러움(카테고리는 토픽이 아님).

**예시**: 2026년 6.3 지방선거, 의료개혁, 스타벅스 탱크데이 논란, 홈플러스 법인회생 절차 신청.

**포함하지 않는 것**

| # | 항목 | 설명 |
|---|------|------|
| T-1 | 특정 사건 | 예: "투표용지 부족" — 이건 이벤트(또는 서브토픽)이지 토픽이 아님 |
| T-2 | 일반 뉴스 카테고리 | 사회·경제·정치·국제 등 카테고리명 단독으로는 토픽이 될 수 없음 |

**루브릭 매핑**

| 기준 | 검사 ID | 판정 방식 |
|------|---------|-----------|
| T-1 (특정 사건 배제) | — | **수동 판정** (Phase 1 골드 라벨) — "이 토픽이 사건 하나가 아니라 이슈 전체를 포괄하는가"는 문맥 판단 필요 |
| T-2 (일반 카테고리 배제) | **R-T2** | 정규식: 루트 토픽 제목이 정치/경제/사회/국제/문화/스포츠/IT 등 카테고리명(+"뉴스"/"소식" 등 일반 접미어) 단독으로만 구성되는지 검사 |
| 네이밍 테스트 | — | **수동 판정** (Phase 1 골드 라벨, 게이트 아닌 참고 지표 — Phase 3 "탐색성 프록시") |
| 중복·고유사 토픽 생성 방지 | **R-T1** | 정규식/유사도: 최상위 토픽끼리 제목 완전 동일 또는 difflib 유사도 ≥ 0.85인 쌍 탐지 (over-create 신호) |

## 서브토픽

**목적**: 동일 토픽 내에서 사용자가 관심 있는 주제의 이벤트를 탐색하기 위한 단위.

**정의**: 기사가 가장 중점적으로 다루는 주제를 기준으로 생성한다.

**생성 기준** (모두 충족해야 함)

| # | 기준 |
|---|------|
| S-생성-1 | 토픽보다 작은 범위여야 함 |
| S-생성-2 | 하나 이상의 이벤트를 포함할 수 있어야 함 (반드시 1개 이상 포함해야 한다는 뜻이 아니라, 여러 이벤트를 담을 수 있는 그릇이어야 한다는 뜻) |
| S-생성-3 | 단순 시간 구분이 아니어야 함 |
| S-생성-4 | 기사의 세부 속성이 아니어야 함 |

**예시**: 의료개혁 → 전공의 / 의대 증원 / 법원 / 의료 공백.

**포함하지 않는 것**

| # | 항목 | 설명 | 예시 |
|---|------|------|------|
| S-1 | 하나의 이벤트만을 의미하는 단위 | 서브토픽은 이벤트의 1:1 별칭이 아님 | — |
| S-2 | 단순 시간 구분 | 날짜·차수 기준으로만 쪼갠 갈래 | "G7 첫째 날", "둘째 날" |
| S-3 | 기사 세부 속성 | 찬반·논조 같은 기사 메타 속성 | "찬성", "반대" |
| S-4 | 토픽과 동일 범위 | 부모 토픽을 그대로 복제한 제목 | — |

**루브릭 매핑**

| 기준 | 검사 ID | 판정 방식 |
|------|---------|-----------|
| S-1 (단일 이벤트 단위 배제) | **R-S1** | 집계: `parent_topic_id IS NOT NULL`인 leaf 토픽 중 연결된 이벤트가 정확히 1개인 비율 |
| S-2 (시간 구분 배제) | **R-S2** | 정규식: 서브토픽 제목에서 "첫째/둘째/셋째 날", "N일차", "N차", "N주차", "N일째" 패턴 탐지 (이벤트 제목에는 이 패턴이 정상적일 수 있으므로 서브토픽 제목만 검사) |
| S-3 (기사 속성 배제) | **R-S3** | 키워드+경계 규칙: "찬성/반대/긍정/부정/옹호/비판"이 제목의 독립된 개념으로 등장하는지 검사 (복합명사 오탐 방지를 위해 공백/일반 접미어 경계를 요구) |
| S-4 (토픽과 동일 범위 배제) | **R-S4** | 유사도: 서브토픽 제목과 부모 토픽 제목의 difflib 유사도 ≥ 0.85 |
| S-생성-1 (토픽보다 작은 범위) | **R-S5** | 집계: 부모(root) 토픽에 이벤트가 직접 붙어 있으면서 그 부모가 서브토픽도 갖는 경우(= leaf 원칙 위반), `parent_topic_id` 체인 깊이가 2를 초과하는 경우 |
| S-생성-2 (이벤트 포함 가능성) | (R-S1과 동일 데이터) | 관측치로 겸용 — 별도 위반 판정 없음 |
| "기사가 가장 중점적으로 다루는 주제" 기준 판단 | — | **수동 판정** (Phase 1 골드 라벨) |

부가 관측: `TOPIC_SUBTOPICS_ENABLED` 활성화 여부와 무관하게 `topics.parent_topic_id IS NOT NULL`
행이 실제로 존재하는지·몇 건인지는 모든 실행에서 리포트에 포함합니다(Phase 0-2의 "서브토픽 데이터
실존 여부" 확인에 재사용).

## 이벤트

**목적**: 현실 세계에서 발생한 하나의 행동(Action) 또는 결정(Decision)을 중심으로 관련 기사들을
하나로 묶는, 타임라인의 최소 단위.

**정의**: 실제로 일어난 행동/결정 하나 = 이벤트 하나.

**예시**: 의료개혁 → 정부 의대 증원 발표 / 전공의 집단 사직 / 업무개시명령 발동 / 법원 집행정지 신청.

**포함하지 않는 것**

| # | 항목 | 설명 |
|---|------|------|
| E-1 | 서로 독립적인 여러 현실 사건 | 별개의 행동/결정을 하나의 이벤트로 과병합하지 않음 |
| E-2 | 하나의 기사에서 함께 언급된 배경·과거 사건 | 본문에 언급되었을 뿐인 과거 맥락은 별도 이벤트로 추출하지 않음 |
| E-3 | 사용자의 관심 주제(서브토픽) | 이벤트는 관심 주제 단위가 아님 — 구조적으로 별개 테이블(`events` vs `topics`)이라 자동 보장됨 |

**루브릭 매핑**

| 기준 | 검사 ID | 판정 방식 |
|------|---------|-----------|
| 이벤트 쪼개짐(과생성) 신호 | **R-E1** | 집계: `event_articles` 매핑 기준 단일기사 이벤트 비율 |
| 이벤트 쪼개짐 의심 신호 | **R-E2** | 유사도: 동일 토픽(`events.topic_id`) 내 difflib 제목 유사도 ≥ 0.8인 이벤트 쌍 |
| E-1 ("동일 현실 사건"인지, 과병합 배제) | — | **수동 판정** (Phase 1 골드 라벨). Phase 3에서 over-merge 정밀도를 별도 게이트로 측정(골드상 다른 사건이 병합된 비율 ≤ 3%) |
| E-2 (배경·과거 사건 배제) | — | **수동 판정** — 프롬프트 레벨 이슈(Phase 2 대상), DB 스냅샷만으로는 "본문에 언급된 배경인지"를 판별할 수 없음 |
| E-3 (서브토픽과 혼동 배제) | — | N/A — 스키마 구조상 자동 보장 (이벤트와 서브토픽은 별도 엔티티) |

## 검사 스크립트 (`eval/rubric_checks.py`)

DB 스냅샷에서 위 루브릭 위반을 자동 산출합니다. 콘솔에 한국어 요약을 출력하고, `--json`으로 기계
판독 가능한 결과를 얻을 수 있습니다.

```powershell
python eval/rubric_checks.py --database-url "postgresql://..."
python eval/rubric_checks.py --json > rubric_report.json
```

`DATABASE_URL` 환경 변수로도 접속 정보를 줄 수 있습니다(`--database-url` 인자가 우선).

검사 ID와 소스 함수 대응은 `eval/AGENTS.md`를 참고하세요.

## 수동 판정 항목 요약 (Phase 1 어노테이션 가이드 입력)

기계 검사로 커버되지 않아 골드 라벨 재작성 시 사람이 판정해야 하는 기준을 모았습니다.

- 토픽 네이밍 테스트("이벤트명 앞에 붙였을 때 자연스러운가")
- 토픽 T-1: 특정 사건이 아니라 이슈 전체를 포괄하는지
- 서브토픽: "기사가 가장 중점적으로 다루는 주제"인지
- 이벤트 E-1: 두 기사가 정말 같은 현실 사건(행동/결정)을 다루는지 — 정정보도·재송고·라이브
  업데이트가 동일 Action인지 규칙 명시 필요 (Phase 1-1 어노테이션 가이드)
- 이벤트 E-2: 기사 본문에서 배경으로만 언급된 과거 사건인지, 별도 이벤트로 추출해야 하는 사건인지
