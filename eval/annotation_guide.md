# 골드 라벨 재라벨 어노테이션 가이드

**작성**: 2026-07-11 | Phase 1-1 산출물 (`.omc/plans/2026-07-10-classification-realignment.md`)
**목적**: `eval/data/gold_labels.json`(dev) + `eval/data/holdout/gold_labels.json`(holdout) 재라벨(Phase 1-2)과
일관성 스팟체크(Phase 1-3)의 헌법. 기존 골드는 옛 정의("반응·해설=별도 이벤트")로 라벨링돼 새 병합 규칙을
오답 처리하므로, 이 가이드가 정하는 규칙대로 처음부터 다시 판정한다.

**정본 관계**: 정의 자체의 정본은 `docs/entity_definitions.md`이다. 이 문서는 그 정의를 기사 하나 앞에서
그대로 적용할 수 있도록 판정 절차·결정 트리·경계 판정례로 구체화한 것이며, 두 문서가 어긋나면
`entity_definitions.md`가 우선한다. 경계 판정례의 근거 자료는
`.omc/research/misclassification-casebook-20260710.md`(실제 프로덕션 오분류 사례집)이다.

## 0. 이 문서를 쓰는 법

1. 재라벨 대상 기사 1건을 연다.
2. **Section 2**로 이벤트를 판정한다 (기존 이벤트에 병합할지, 새 이벤트를 만들지).
3. **Section 3**으로 그 이벤트가 속할 서브토픽을 판정한다.
4. **Section 4**로 그 서브토픽(또는 서브토픽이 없다면 이벤트)이 속할 토픽을 판정한다.
5. `gold_labels.json`에 `{article_guid: {gold_topic, gold_subtopic, gold_event}}`을 기록하고, 신규
   이벤트/서브토픽/토픽이면 taxonomy 파일에도 노드를 추가한다 (형식은 Section 1).
6. 애매한 사례를 만났는데 이 가이드의 기존 규칙으로 판정이 안 되면, 가장 가까운 경계 판정례(Section 2.7)와
   비교해 판정한 뒤 **부록**에 새 판정례를 추가한다. 가이드는 재라벨을 진행하며 계속 자란다.

## 1. 라벨 스키마와 절차

### 1.1 `gold_labels.json` 형식

`eval/data/gold_labels.json`과 `eval/data/holdout/gold_labels.json`은 동일 스키마다: 기사 `guid`를
키로, 3단 계층 정답 ID를 값으로 갖는 평평한 딕셔너리.

```json
{
  "dummy-E001-0": {
    "gold_topic": "T001",
    "gold_subtopic": "S001",
    "gold_event": "E001"
  }
}
```

- `gold_topic` / `gold_subtopic` / `gold_event`는 각각 `eval/taxonomy/gold_taxonomy.json`(또는 holdout은
  `holdout_taxonomy.json`)에 정의된 `topics[].id` / `subtopics[].id` / `events[].id`를 가리킨다.
- 서브토픽이 없는(=토픽에 이벤트가 직결된) 경우의 표기 규칙은 기존 파일에 실례가 없으므로, Phase 1-2에서
  최초로 그런 사례가 나오면 이 문서 부록에 확정 표기법을 기록한다.

### 1.2 `gold_taxonomy.json` 형식

```json
{
  "_readme": { "...": "스키마·gold_cases 설명 (로더는 무시, 사람만 읽음)" },
  "topics": [
    {
      "id": "T001", "title": "...", "category": "국제",
      "subtopics": [
        {
          "id": "S001", "title": "...",
          "events": [
            {
              "id": "E001", "title": "...", "category": "국제",
              "gold_case": "cross_publisher",
              "gold_case_desc": "...",
              "gold_event_ref": "E001",
              "base_date": "2026-06-20",
              "base_facts": "...",
              "num_articles": 6,
              "article_variants_hint": ["..."]
            }
          ]
        }
      ]
    }
  ]
}
```

`events[].gold_event_ref`가 자기 자신이 아닌 다른 이벤트 id를 가리키면, 그 이벤트 노드의 기사들은
실제로는 `gold_event_ref`가 가리키는 이벤트로 병합되어야 한다는 뜻이다 (`_readme.gold_cases.time_window`
케이스에서 쓰임 — 2일 탐색 윈도우 밖의 후속 기사가 원 이벤트로 회수되는지 시험하는 용도). 재라벨 시
새 이벤트 노드를 추가할 때도 이 필드로 "이 노드는 표현상 별도 기재하지만 실제 gold는 다른 이벤트"를
표시할 수 있다.

### 1.3 재라벨 작업 순서

기사 읽기 → 이벤트 판정(Section 2) → 서브토픽 판정(Section 3) → 토픽 판정(Section 4) → 기록. 반드시
이 순서로 진행한다 — 실제 파이프라인도 이벤트 추출이 먼저이고, 서브토픽·토픽은 이벤트를 입력으로 받는
구조이기 때문에 (`src/event_classifier/` → `src/topic_classifier/`) 거꾸로 판정하면 상위 단위를 먼저
정해놓고 이벤트를 끼워 맞추는 오류가 생기기 쉽다.

이 문서는 **판정 규칙**을 고정하는 것이며, Phase 1-2에서 실제 프로덕션 사례를 어떤 `guid`/파일 구조로
옮겨 담을지(예: 실제 기사 id를 `guid`로 쓸지, taxonomy를 어떻게 확장할지)는 Phase 1-2 실행 시점에 결정할
사항으로 이 가이드의 범위 밖이다.

## 2. 이벤트 동일성 판정 (핵심)

### 2.1 판정 기준

`docs/entity_definitions.md`의 이벤트 정의: **"현실 세계에서 발생한 하나의 행동(Action) 또는
결정(Decision)"**. 두 기사가 같은 이벤트인지는 제목 유사도나 매체·톤이 아니라 **"이 기사가 보도하는
행동/결정의 주체(행위자)와 구체적 내용이 다른 기사와 같은가"**로만 판정한다.

제목 유사도는 신호일 뿐 증거가 아니다. 사례집 B5(`event_id=205`, 사그라다 파밀리아 완공 다각 보도)는
평균 제목 유사도 0.227로 낮지만 **같은 완공이라는 하나의 사건**을 건축적 의의·관광 영향·현지 반응 등
다른 각도로 보도한 것뿐이므로 정상 병합이다. 반대로 사례집 A1(잠실 개표소 봉쇄 시위, `event_id`
1495/982/1019/…12건)은 제목이 **완전히 동일**한데도 12개 이벤트로 쪼개져 있다 — 이건 후보검색이 전혀
붙지 못한 파이프라인 결함이지 실제로 12개의 서로 다른 사건이 존재하는 게 아니다. 즉 제목 유사도가
높든 낮든, 최종 판정은 반드시 "행동/결정이 같은가"로 내린다.

### 2.2 판정 결정 트리

```
Q1. 이 기사가 다루는 핵심 사실이 현재 벌어진 행동/결정인가, 아니면 그 배경으로 언급된 과거 사건인가?
 ├─ 배경으로 언급됐을 뿐 (본문의 부차적 맥락) → E-2 위반, 이벤트로 추출하지 않음 (2.5절)
 └─ 현재 발생한 행동/결정을 다룸 → Q2

Q2. 같은 토픽/서브토픽 안에 이미 있는 후보 이벤트 중, 같은 행위자가 벌인 같은 구체적 행동/결정을
    다루는 이벤트가 있는가? — 판단 기준은 "앵커 결정-과정 테스트"(Anchor Decision-Process Test):
    이 기사는 (a) 후보 이벤트가 이미 착수한 하나의 결정 절차가 진행되거나 결론에 이르는 것을
    보도하는가, 아니면 (b) 별도의 의사결정 주체가 새로운/독자적인 결정을 내린 것을 보도하는가?
 ├─ (a) 같은 결정 절차의 진행/결론 → 기존 이벤트에 배정 (2.3절의 병합 규칙 적용)
 └─ (b) 별도의 독자적 결정 → 신규 이벤트 생성 (2.4절의 분리 규칙 확인 후 2.6절 명명 규칙으로 제목 작성)
```

### 2.3 병합 규칙 (같은 이벤트로 판정)

다음은 모두 "같은 결정 절차의 진행/결론"에 해당하므로 **하나의 이벤트로 병합**한다. 팀리드가 지정한
경계 판정례 a~g를 이 규칙 아래 명시적으로 배치한다.

**a. 정정보도** — 원 보도가 다룬 것과 **같은 행동/결정**의 사실관계를 바로잡는 정정 기사는 원 이벤트에
병합한다 (예: "투표율 62%"라던 최초 보도를 "61.8%"로 정정 — 같은 개표 발표를 다룸). 단, **정정
자체가 새로운 사회적 사건이 되는 경우**(예: 정정으로 인해 담당자 징계, 공개 사과, 소송 등 새로운
행동/결정이 뒤따르는 경우 — 가상의 예시)는 그 새로운 행동/결정만 별도 이벤트로 분리한다. 원 보도의
정정 자체는 여전히 원 이벤트에 남는다.

**b. 재송고/통신사 중복** — 같은 결정/사건을 서로 다른 매체가 통신사 배포로 그대로 싣거나 자체 기사로
다시 쓴 경우는 항상 같은 이벤트다. `gold_taxonomy.json`의 `cross_publisher` 케이스(예: E001 한미 FTA
3차 협상, 진보/중도/보수 매체 6편)가 정확히 이 패턴이며, 병합이 기본이지 예외가 아니다.

**c. 라이브 업데이트(진행 중 상황 갱신)** — 같은 사건이 시간에 따라 전개되는 것을 새로운 결정 주체
없이 갱신 보도하는 경우는 병합한다. `holdout_taxonomy.json`의 산불 스레드가 실례다: E013(강원 고성
산불 발생·초기 대응) → E014(사흘째 확산 지속) → E015(완전 진화·피해 집계) 세 노드 모두
`gold_event_ref=E013`로 **하나의 이벤트**다. 화재가 커지고 진화되고 피해가 집계되는 것은 새 의사결정
주체가 개입하는 게 아니라 같은 물리적 사건이 시간순으로 전개되는 것이기 때문이다. 반대로, 전개
도중 새로운 독자적 결정이 등장하면(예: 산불 진화 도중 정부가 별도로 "특별재난지역 선포"를 결정) 그
결정은 별도 이벤트로 분리한다 — Q2의 (b) 경로.

**d. 사례집 B2 (`event_id=2617`, 국민의힘 6곳 선거소청 결정)** — 소청 결정 자체와 그에 대한 지도부
공방(반응 발언)이 한 이벤트에 섞여 있다. 새 정의 판정: 지도부 공방이 **결정에 대한 반응·논평**(찬반
발언, 비판, 해석)에 그친다면 새로운 행동/결정을 구성하지 않으므로 소청 결정과 **같은 이벤트로 유지**한다.
단 공방 과정에서 예컨대 지도부가 재심 청구·징계·해임 같은 **자체 결정**을 내리면 그 결정은 별도
이벤트로 분리한다. B2 사례 자체는(현재 기술된 정보상) 공방이 발언 수준이므로 병합이 맞다.

**e. 사례집 B4 (`event_id=1825`, 울산지방노동위원회 판정 통보)** — 판정 통보 기사와 그 후속 파장을
다룬 기사가 섞여 있다. "후속 파장 보도"가 같은 판정에 대한 추가 취재·영향 분석·당사자 반응이라면
후속보도 병합 규칙 그대로 **같은 이벤트**다. 후속 파장 보도 안에서 노동위·회사·노조 중 누군가 새로운
독자적 조치(예: 회사의 재심 신청, 노조의 고소)를 발표했다면 그 조치만 분리한다.

**f. 사례집 B5 (`event_id=205`, 사그라다 파밀리아 완공 다각 보도)** — 위 2.1절에서 다뤘듯, 낮은 제목
유사도(0.227)에도 불구하고 같은 완공이라는 하나의 사건을 다각도로 보도한 것이므로 **정상 병합**이다.
이 사례는 "제목 유사도가 낮다"는 자동 신호를 뭉침 의심의 근거로 오독하면 안 된다는 것을 보여주는
표준 반례로 삼는다 — 판정은 항상 행동/결정 동일성으로 한다.

**g. 사례집 A2/A4/A5 ("~사태/다툼"류 지속 상황) 분리 절차** — "사태", "다툼", "논란" 같은 포괄
명칭은 그 자체로 이벤트가 될 수 없다(서브토픽에 가까운 개념). 이런 그룹을 재라벨할 때는:

1. 그룹 내 각 기사에서 "구체적으로 어떤 행동/결정을 보도하는가"를 개별적으로 추출한다 (상위
   사태명이 아니라 실제 문장 단위 사실).
2. 동일한 구체적 행동/결정끼리만 묶는다.
3. 제목이 완전히 동일해도(중복 탐지 실패로 인한 파편일 가능성이 높음) 실제로 서로 다른 시점의
   서로 다른 구체적 결정을 다룬다면 별도 이벤트로 분리한다.
4. 정말 같은 특정 발언/성명/회견 하나만 반복 보도된 경우에만 1개로 유지한다.

적용례:
- **A5(`선관위 투표용지 부족 사태`, 6건 중복 `559/687/810/854/1547/2663`)**: "부족 인정 발표"와
  "재발 방지 대책 발표"는 같은 행위자(선관위)의 **서로 다른 시점, 서로 다른 구체적 결정**이므로,
  기사를 열어 실제로 어느 쪽을 다루는지 확인해 2개(또는 그 이상) 이벤트로 분리해야 한다. 단순히
  "부족 사태를 계속 보도"하는 상태 갱신 기사만 있다면 1개로 유지한다.
- **A2(`정청래 사퇴 요구 및 전당대회 준비`, 7건 중복 `321/644/556/595/837/1249/2613`)**: "사퇴
  요구"와 "전당대회 준비"는 표면적으로 다른 행동으로 보인다. 7건이 모두 같은 시점의 같은 성명/회견을
  보도한 것이면 1개로 병합하되, 실제로 사퇴 요구 국면과 전당대회 준비 국면이 시점상 분리된다면
  2개로 쪼갠다. 반드시 기사 본문을 열어 확인한다 — 제목만으로 판정하지 않는다.
- **A4(`여야 법사위원장 자리 다툼`, 6건 중복 `1683/1510/1392/1331/1248/1478`)**: 같은 절차로,
  "위원장직 요구 발언" 단계와 "실제 표결/합의" 같은 구체적 결정 단계가 섞여 있는지 확인 후 분리
  여부를 정한다.

### 2.4 분리 규칙 (다른 이벤트로 판정)

다음은 "별도의 독자적 결정"에 해당하므로 **분리**한다:

- **서로 다른 의사결정 주체가 각자의 결정을 내림** — `docs/entity_definitions.md`의 정본 예시가
  그대로 기준이다: 정부 의대 증원 발표 / 전공의 집단 사직 / 업무개시명령 발동 / 법원 집행정지 신청은
  4개의 서로 다른 행위자(정부·전공의·정부·법원)가 각자 결정한 것이므로 4개의 별도 이벤트다.
  `holdout_taxonomy.json`의 E101(정부 의대 정원 2천 명 증원 발표)~E105(정부 비상진료체계
  가동·군의관 투입)도 같은 패턴을 5개 이벤트로 반영한다.
- **같은 행위자이지만 시점이 다른, 형식적으로 별개인 구체적 결정** — 예: `holdout_taxonomy.json`의
  E101(증원 목표 인원 발표)과 E102(대학별 배정 확정)는 같은 정부의 결정이지만 발표 시점과 결정
  내용(총원 vs 학교별 배정표)이 서로 다른 별개의 행정 결정이므로 `gold_event_ref`가 자기 자신을
  가리키며 **분리 유지**된다. "후속 보도"라는 표면적 딱지가 붙어도 실제로 새로운 구체적 결정이면
  분리한다 — 병합 규칙(2.3절)은 "같은 결정의 진행/결론"에만 적용되지, "관련된 다음 소식"이면 전부
  적용되는 게 아니다.
- **반응이 그 자체로 새로운 행동/결정을 구성하는 경우** — 단순 발언·논평이 아니라 사퇴, 고발, 지시
  철회, 재심 청구처럼 그 자체가 하나의 결정이면 별도 이벤트다.

부정 사례(뭉침으로 판정해 반드시 분리해야 하는 실례):
- **사례집 B1(`event_id=3118`, 교권 회복 운동·입법화, 5건, 평균 유사도 0.176)**: '모두의 학교' 정책
  발표 / 공교육 멈춤의 날 (집단행동) / 서이초 49재 추모집회 — 서로 다른 주체가 서로 다른 시점에
  일으킨 최소 3개의 독립적 행동/결정이 하나의 이벤트에 뭉쳐 있다. **3개 이상으로 분리**해야 한다.
- **사례집 B3(`event_id=374`, "6·3 지방선거 투표용지 부족 사태 규탄 시위대가…", 4건, 평균 유사도
  0.178)**: 개표소 봉쇄 시위와 체육단체의 피해 호소는 서로 다른 행위자 집단의 서로 다른 행동이므로
  **분리**한다. (이 이벤트는 제목도 문장형이라 2.6절 명명 규칙도 위반 — 이중 위반 사례.)

### 2.5 배경·과거 사건 제외 (E-2)

기사 본문에 함께 언급된 배경·과거 맥락은 별도 이벤트로 추출하지 않는다. 사례집 `#790`("1950년
6·25전쟁 발발 후… 학도병 조직과 피란학교 설립을 통해 전쟁 중 교육 지속을 시도했다")이 전형적
위반 사례다 — 이건 현재 벌어진 행동/결정이 아니라 순수 역사 배경 서술이므로 애초에 이벤트가 아니다.
DB 스냅샷만으로는 "본문에 언급된 배경인지"를 기계 판정할 수 없으므로 반드시 기사 본문을 읽고
사람이 판정한다.

### 2.6 이벤트 명명 규칙

이벤트 제목은 **"행위자 + 행동/결정 명사형"**으로 쓴다. 문장형(주어+서술어로 끝나는 완결된 문장)은
금지한다. 위반 사례(사례집 C):

- `#790`: "1950년 6·25전쟁 발발 후 대한민국 정부는 학도병 조직과 피란학교 설립을 통해 전쟁 중 교육
  지속을 시도했다." — 문장형이며 애초에 E-2 위반(배경 서술)이기도 한 이중 위반.
- `#2850`: "명지대가 지난달 14일부터 15일까지 … 사업 추진 방향을 논의했다." — 문장형.
- `#1489`: "비정규직 노동자들이 이재명 정부 출범 1주년을 맞아 근로기준법 전면 적용을 가장 시급한
  과제로 꼽았다." — 문장형.

준수 사례(정본): "정부 의대 증원 발표", "전공의 집단 사직", "업무개시명령 발동", "법원 집행정지
신청" — 모두 행위자를 주어처럼 앞세우고 행동을 명사형 어미("발표", "사직", "발동", "신청")로
맺는다. 재라벨 시 문장형 제목을 만나면 핵심 행위자와 행동만 추려 이 형식으로 다시 쓴다.

## 3. 서브토픽 판정

`docs/entity_definitions.md`의 정의: 서브토픽은 **"기사가 가장 중점적으로 다루는 주제"**를 기준으로
생성하며, 토픽보다 작은 범위여야 하고, 단순 시간 구분·기사 속성·토픽과 동일 범위여서는 안 된다
(불포함 4규칙 S-1~S-4). 예시 구조: 의료개혁(토픽) → 전공의 / 의대 증원 / 법원 / 의료 공백
(서브토픽들). `holdout_taxonomy.json`의 의료개혁 유사 스레드(E101 증원 발표, E102 배정 확정, E103
전공의 사직, E104 총파업 투표, E105 비상진료체계)를 이 구조에 대입하면: E101·E102 → "의대 증원"
서브토픽, E103·E104 → "전공의" 서브토픽, E105 → "의료 공백" 서브토픽으로 나뉜다.

### 3.1 불포함 4규칙

**S-1 (단일 이벤트만을 의미하는 단위 금지)** — 서브토픽은 이벤트의 1:1 별칭이 아니다.

- 양성(허용): "의대 증원" — E101(증원 발표)과 E102(배정 확정) 등 여러 이벤트를 담을 수 있는 그릇.
- 음성(위반): 서브토픽 제목을 "정부 의대 2천 명 증원 발표"로 짓는 것 — 이건 E101 이벤트 제목을
  그대로 복사한 것으로 S-1 위반.

**S-2 (단순 시간 구분 금지)** — 날짜·차수 기준으로만 쪼갠 갈래는 서브토픽이 될 수 없다.

- 양성: "전공의" — 사직부터 파업 투표까지 시간과 무관하게 유지되는 테마.
- 음성: "필리버스터 5일차", "산불 사흘째" 처럼 날짜/차수를 서브토픽명에 쓰는 것. (참고: 같은 문구가
  **이벤트** 제목의 부속 설명으로 등장하는 것과는 다르다 — 이 규칙은 서브토픽 제목에만 적용된다.
  실제로 산불 사례는 이벤트 자체가 E013 하나로 병합되므로 애초에 "사흘째"라는 서브토픽이 생길
  이유가 없다.)

**S-3 (기사 세부 속성 금지)** — 찬반·논조 같은 메타 속성은 서브토픽이 될 수 없다.

- 양성: "의료 공백" — 파업으로 인한 결과라는 사건 묶음 기준.
- 음성: 의료개혁 토픽 아래 "증원 찬성" / "증원 반대" 서브토픽을 만드는 것 — 이건 기사의 논조이지
  사건 묶음 기준이 아니다.

**S-4 (토픽과 동일 범위 금지)** — 부모 토픽 제목을 그대로 복제한 서브토픽 제목은 금지.

- 양성: "전공의" / "의대 증원" / "법원" / "의료 공백" — 각각 "의료개혁"보다 명백히 좁다.
- 음성: 토픽 "의료개혁" 아래 서브토픽 "의료개혁 관련 사건"을 만드는 것 — 범위가 부모와 같다.

### 3.2 "가장 중점적으로 다루는 주제" 판정

한 이벤트(또는 기사)가 여러 서브토픽 후보에 걸칠 수 있다. 예: "전공의 집단사직으로 응급실 마비"
기사는 "전공의"(행위자)와 "의료 공백"(결과) 양쪽에 걸린다. 이때는 기사가 **가장 비중 있게 다루는
사실**이 무엇인지로 정한다 — 위 예시가 응급실 마비 상황과 대응을 중심 서술로 삼는다면 "의료 공백"에,
전공의 측 결정과 명분을 중심 서술로 삼는다면 "전공의"에 배정한다. 이 판정은 기계 검사로 커버되지
않으므로(정본 문서 표기: 수동 판정) 애매하면 기사 리드문(첫 2~3문장)이 어느 쪽을 다루는지를 1차
기준으로 삼는다.

## 4. 토픽 판정

### 4.1 정의와 포함 기준

토픽은 "인과관계, 동일 이슈, 동일 일정, 동일 사회적 현상으로 묶이는 사건들의 집합"이다. 포함하지
않는 것: **T-1** 특정 사건 하나(예: "투표용지 부족"은 이벤트/서브토픽이지 토픽이 아님), **T-2**
일반 뉴스 카테고리 단독(정치/경제/사회/국제 등 + "뉴스"/"소식" 같은 접미어만으로 구성된 제목).
T-2는 `eval/rubric_checks.py`의 `R-T2`로 기계 검사되지만, T-1("이 토픽이 사건 하나가 아니라 이슈
전체를 포괄하는가")은 문맥 판단이 필요해 **수동 판정**이다.

### 4.2 네이밍 테스트 (참고 지표, 게이트 아님)

각 이벤트명 앞에 토픽명을 붙였을 때("<토픽명> — <이벤트명>") 자연스러운지 확인한다. 예:
"2026년 6.3 지방선거 — 사전투표 부실 논란"은 자연스럽지만 "사회 — 사전투표 부실 논란"은
부자연스럽다(카테고리는 토픽이 아님). **이 테스트는 판정을 확정하는 게이트가 아니라 T-1/T-2가
불확실할 때 참고하는 보조 지표다** — Phase 3 게이트에서도 "탐색성 프록시"라는 관측 지표로만 쓰이고
합격/불합격 기준이 아니다. 네이밍 테스트만으로 애매한 경우 최종 판정은 4.1절 T-1/T-2 기준으로
내린다.

## 5. 일관성 스팟체크 절차 (Phase 1-3)

1. dev + holdout 라벨을 모두 확정한 뒤, 라벨링된 이벤트(또는 이벤트-병합 판정 단위)의 **무작위
   20%**를 표본으로 뽑는다.
2. 표본을 원 판정 결과를 보지 않고(블라인드) **재판정**한다. 가능하면 원 작업자가 아닌 다른
   사람이 재판정하고, 인원이 한 명뿐이면 최소 하루 이상 간격을 두고 원 라벨을 참조하지 않은 채
   같은 작업자가 재판정한다.
3. **일치율 ≥ 90%**를 요구한다. 일치율은 이벤트 병합/분리 판정, 서브토픽 배정, 토픽 배정 각각에
   대해 별도로 측정한다.
4. 불일치가 발견되면:
   - 불일치 사례가 이 가이드의 어느 규칙(2.2~2.4, 3.1, 4.1)과 관련되는지 식별한다.
   - 그 규칙 아래(또는 부록)에 새 판정례를 명시적으로 추가해 규칙을 구체화한다.
   - **해당 유형에 속하는 전체 라벨을 재검토**한다 (표본 20%만이 아니라, 같은 패턴의 모든 기존
     라벨을 새 규칙으로 다시 확인). 이건 Phase 1-3의 목적이 "표본 통과"가 아니라 "가이드 자체의
     완결성 확인"이기 때문이다.
   - 재검토 후 다시 무작위 표본 재판정 → 90% 이상이 나올 때까지 반복한다.
5. 최종 일치율과 발견된 판정례 추가 이력을 부록에 기록한다.

## 6. holdout 분할 규칙

**원칙**: 동일 이슈(연속된 사건들의 스레드)가 dev와 holdout에 걸쳐 나뉘면 안 된다 — 시간 누수(temporal
leakage) 방지. 파이프라인이 dev로 학습/튜닝된 뒤 holdout에서 "같은 이슈의 나머지 절반"을 평가하면
실제 일반화 성능이 아니라 이슈 자체를 이미 봤다는 이점만 측정하게 된다.

**분할 단위**: 개별 기사나 개별 이벤트가 아니라 **이슈 스레드** 전체를 원자 단위로 취급한다. 이슈
스레드는 실무적으로 "같은 서브토픽 안에서 시간적으로 연속된 이벤트들의 집합"으로 정의하며, 이는
프로덕션 파이프라인이 유지하는 토픽별 이벤트 prev/next 체인(`src/topic_classifier/`)과 대응한다.
예: `holdout_taxonomy.json`의 노동개혁 스레드(E005 법안 제출 → E006 필리버스터 5일차 →
E011 본회의 강행 처리, 모두 `gold_event_ref=E005`로 한 이벤트)나 산불 스레드(E013→E014→E015)는
전체가 하나의 분할 단위이며 dev/holdout 중 한쪽에만 통째로 들어가야 한다. Section 2.4에서 분리로
판정한 이벤트들(예: A5의 "부족 인정 발표"와 "재발 방지 대책 발표"가 2개 이벤트로 나뉘는 경우)도
같은 사태에서 파생됐으므로 **한 세트로 묶어 같은 쪽에 배치**한다 — 이벤트가 갈라져도 이슈 스레드는
하나다.

**검증**: 새로 라벨링하는 이슈 스레드마다 발행일 구간(`base_date`/기사 `published_at`)을 확인해,
dev에 넣은 스레드의 시간 구간과 holdout에 넣은 스레드의 시간 구간이 같은 실사건을 가리키며 겹치지
않는지 점검한다. 이미 존재하는 `holdout_taxonomy.json`은 `gold_taxonomy.json`(dev)과 겹치는 도메인이
없는 완전 별도 세트로 설계되어 있으므로(`eval/taxonomy/AGENTS.md`), Phase 1-2에서 casebook 실사례를
추가할 때도 이 원칙 — 완전 분리된 이슈 단위로 dev/holdout에 배정 — 을 그대로 따른다.
